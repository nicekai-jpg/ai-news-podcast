# KG 实体与关系抽取方案评测复盘（2026-11-19）

> 结论：在 18 篇 dev/test 金标上，所有非 LLM 三元组方案在留出集的 F1 最高 0.11；
> “主语准入 + 客体分类 + 类型兼容”这组过滤型规则被证伪（dev 涨、test 降）。
> 规则路线到此为止，改用候选召回与微调两条线。

## 一、结论摘要

**先分清两件事：本文评测了两个独立任务，数字不能混用。**

| 任务 | 金标 | 评判标准 | 最佳 F1 |
|---|---|---|---|
| A 实体抽取 | 3 篇 / 47 个实体提及 | 文本归一后一致 + 类型正确 | 0.66 |
| B 三元组抽取 | 18 篇 / 54 条三元组 | 关系一致 + 两端包含匹配 | 0.11 |

```
任务 A：只输出实体
  文本 → 实体列表 [(文本, 类型)]
  例   → [("DiamNEX", ORG), ("耀途资本", ORG), ("深圳", LOC)]

任务 B：输出三元组
  文本 → [(主语, 关系, 宾语)]
  例   → [("DiamNEX", funding, "耀途资本")]
  依赖 实体 + 关系 + 论元三者同时正确
```

两者不是同一把尺子：任务 B 的错误会在实体、关系、论元三处叠加，所以 A 的 0.66 不代表 B 能到 0.66。

| 项目 | 结果 |
|---|---|
| 实体层最佳 | F1 0.66（HanLP ∪ GLiNER2 + 泛词过滤） |
| 关系层 dev 最佳 | F1 0.34（并集候选 + 过滤） |
| 关系层 test 最佳 | F1 0.11（SRL 原始候选） |
| 主要瓶颈 | 候选召回 8% |
| 被证伪的设计 | 过滤器型规则（R1/R2/R3） |

## 五、失败归因

54 条金标三元组，按候选池状态分类：

| 状态 | 数量 | 例子 |
|---|---|---|
| 完全命中 | 10 | — |
| 关系对、端点错 | 15 | `funding 独家丨港大孵化的半导体材料公司 => 数千万` |
| 端点对、关系错 | 2 | `open_source 补丁 => Linux`（应为 support） |
| 两者皆无 | 27 | `award DiamNEX => 日内瓦发明展金奖` |

```
54 条
 ├─ 有候选                     27 条（50%）
 │    ├─ 命中                   10
 │    └─ 端点/关系错             17
 └─ 无候选                     27 条（50%）  ← 主因
```

候选池覆盖只有一半，过滤类规则无法创造召回；实体吸附只能修 span，修不了论元选择。

## 五点五、结论

| 假设 | 结果 |
|---|---|
| SDP 边可补 SRL 缺 A0 | 证伪，dev 召回 0% |
| 实体吸附可修端点错误 | 证伪，召回不变 |
| 过滤器规则可提升 F1 | 证伪，test 单调下降 |

## 五点六、组合网格（72 组）

覆盖 6 个候选源 × 3 套实体集 × 4 种过滤：

```
候选源  SRL / SDP / JointIE / SRL+SDP / SRL+JIE / ALL
实体集  仓库 jieba / HanLP / HanLP∪GLiNER
过滤    F0 无 / F1 主语准入 / F2 主语+客体 / F3 +类型兼容
```

| 排名口径 | 组合 | dev | test |
|---|---|---|---|
| test 最高 | SRL + F0 | 0.26 | 0.11 |
| dev 最高 | SRL+JIE + 仓库实体集 + F1 | 0.39 | 0.07 |

结论：**72 组里 test F1 最高 0.11，且是不过滤的朴素组合**；所有能抬高 dev 的过滤，在 test 上都回落。实体集选择在 F0 下不产生影响（F0 不使用实体集）。

## 六、被推翻的假设

| 原假设 | 留出集实测 |
|---|---|
| 主语约束可提升 F1 | dev 0.28 / test 0.09 |
| 客体分类可提升 F1 | dev 0.26 / test 0.05 |
| 类型兼容可提升 F1 | dev 0.18 / test 0.00 |
| 规则天花板 0.25~0.3 | 0.11 |

原因：这些规则是在同一批数据上设计并验证的，属于过拟合。

## 七、调整后的方案

```
阶段 0  评测基建
        金标扩到 50 篇，冻结 test 35 篇
        每次改动只在 dev 开发，test 只验收一次

阶段 1  候选召回（只看 recall@候选池）
        来源 A  SRL 帧
        来源 B  SDP 语义依存边（Agt / Pat）
        来源 C  主语继承 + 依存主谓宾
        目标    候选召回 >= 50%

阶段 2  候选过滤（只看 precision）
        泛词/长度/代词
        弱类型约束（不硬性要求 company）
        目标    recall 30% 时 precision >= 40%

阶段 3  决策点
        F1 < 0.35 → 停止规则，转微调
        F1 >= 0.35 → 进入打分与 A/B 分级
```

### 与旧方案的区别

| 项 | 旧 | 新 |
|---|---|---|
| 先做哪步 | 先过滤 | 先提召回 |
| 验收方式 | dev/test 同批 | dev 开发 / test 冻结 |
| 类型兼容 | 硬矩阵 | 弱约束 |
| 失败判据 | 无 | F1 < 0.35 即停 |
