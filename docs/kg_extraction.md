> 版本：v0.6（去掉省事限制，补多情况覆盖）
> 状态：已实施（2026-11-16，Stage 2.5；验证记录见交付说明）
> 代码基线：`business/kg/`（V1 抽取器）、v3 流水线 Stage 2.5
> V1 现状说明归档：[archive/kg_extraction_v1.md](archive/kg_extraction_v1.md)
> 本版变化：删掉所有「为了省事」的上限；英文、全句、21 类关系、省略主语、被动句、多格式来源全部纳入范围

## 0 一页速览

| 项 | 内容 |
|---|---|
| 设计目标 | 从新闻抽「谁 · 做了什么 · 涉及谁/什么/多少钱」 |
| 实现约束 | 全链零 LLM、零网络、可重复 |

## 1 设计依据（为什么这么设计）

### 1.1 现状问题

| 指标 | 数值 | 出处 |
|---|---|---|
| V1 三元组（10 篇量子位） | 65 条 | `data/kg_audit/kg_batch.json` |
| 我逐条核对可用 | 12 条 | 人工核对 |
| 可用率 | 18% | 12 ÷ 65 |
| 置信 0.9 的边 | 4 条 | 4 条全对 |
| 拆子句后能拿到干净主谓宾 | 39 / 65 | spaCy 试探脚本 |

根因一句话：用「动作前后最近的实体」判主宾，不用句法角色。

### 1.2 技术验证（本机实测，2026-11-16）

| 验证项 | 结果 |
|---|---|
| spaCy 版本 | 3.8.18 |
| 中文模型 | zh_core_web_sm 3.8.0 |
| 模型管线 | tok2vec、tagger、parser、attribute_ruler、ner |
| 分词错例 | 英伟达 → 英伟 + 达 |
| 分词错例 | DeepSeek → Deep + Seek |
| 词表 span 合并 | 合并后依存正确：英伟达 nsubj → 任命 |
| 自定义管线组件 | 可用：组件放首位做 retokenize，支持批量解析 |
| 并列主语 | 联想集团和张家口市政府签署 → 主语是市政府，集团是 conj |
| 引述句 | 消息称，联想正与某地方政府洽谈 → 真实事件在 ccomp |
| 否定 | 「并没有」是 advmod，不是 neg 依赖 |
| 枚举宾语 | Search、Fetch…等接口 → dobj 是 Fetch，接口挂在动词 conj |

### 1.3 真实一天数据（2026-11-16，v3 artifact 实测）

来源：GHA artifact `v3-output-2026-11-16` 里的 ocean 产物。

| 指标 | 实测 |
|---|---|
| items | 571 条 |
| events | 470 个 |
| 事件有全文代表条目 | 414 个 |
| 句子总数 | 16,790 句 |
| 平均句长 | 86.6 字 |
| 超 300 字长伪句 | 277 句 |
| 英文条目 | 183 条 |
| 英文有全文 | 106 条 |
| 只有摘要的条目 | 116 条 |
| 标题含词表实体 | 230 条 |
| Stage 2 有 actions 标签 | 402 条 |
| actions 标签空白事件 | 24% |
| subjects 标签空白事件 | 44% |
| 重复条目 | 116 条 |
| 跨天重复条目 | 321 条 |
| 超 8000 字全文 | 37 条 |
| 无 event_id 条目 | 14 条 |
| 提到「微信」 | 110 条 |
| 「微信 + 发布」句 | 21 句 |
| 解析速度 | 1.3 毫秒/句（42 字句，本机） |

五条修正：

1. 量比设计估的小：571 条 item、470 个事件，不是 1000–1500；
2. 全文解析很便宜：约 2 分钟，控量不必牺牲召回；
3. 重复太多：20% 是重复条目、321 条是跨天重复，按条目跑会重复入库；
4. 噪声词要窄化：「微信」这类词会误杀真新闻；
5. 英文必须做：183 条英文、106 条有全文，跳过等于丢 1/3 覆盖。

### 1.4 原型验证

| 原型 | 输入 | 结果 |
|---|---|---|
| 原型 A | 65 条 V1 边原句 | 抽到 13 条候选，手看约 6 条可用 |
| 原型 B | 2 篇真实文章 800 字导语 | 英伟达文抓到 2 条正确事实 |
| 原型 B | 2 篇真实文章 800 字导语 | 基准文 0 条（事实在文中部） |
| 原型 C | 全文 + 实体/动作词预筛 | 12 句内能定位事件句 |

### 1.5 设计结论

| 决策 | 内容 |
|---|---|
| 迭代单位 | 按事件，一条新闻一个卡集 |
| 扫描范围 | 标题 + 全文所有句子 |
| 控量方式 | 长句转分句；单条超 500 句才截断 |
| 主判据 | 句法主语/宾语，不用距离 |
| 语言 | 中文和英文都做 |
| 关系范围 | 21 类全部 |
| 不准怎么办 | 判 C 丢弃，不猜；C 样本留档周审 |

## 2 总体设计

### 2.1 位置与边界


### 3.2 四个中间结构

```
事件 ─► 代表条目 ─► 解析结果 ─► 谓词 ─► 候选事实 ─► 事实卡
                        │
                        └─ 词表 span（实体位置，含在解析结果里）
```

| 结构 | 作用 | 关键内容 |
|---|---|---|
| 解析结果 | 一个子句的完整解析 | 原文、token 列表、词表 span、root 下标 |
| 谓词 | 一个动作及其论元 | 动词、主语、宾语、补语、介词宾语 |
| 候选事实 | 判档前的半成品 | 主体、关系、槽位、极性、情态、理由、证据 |
| 事实卡 | 落盘的最终结构 | 见 3.3 |

| dep | 批量解析 | 子句列表 | 解析结果列表 | 单条跳过 |
| dep | 谓词抽取 | 解析结果 | 谓词列表 | 空 |

### 5.2 编排流程

```
① 读配置、加载词表
   │
   ▼
② 加载解析器；失败且要求解析 → 返回空结果
   │
   ▼
③ 建立 item → 事件 映射
   │
   ▼
④ 逐事件循环
   │   选代表条目 → 选句 → 分句
   │   批量解析 → 谓词 → 关系 → 填槽 → 判档
   │   追加事实卡，累计统计

```

### 6.3 dep.py：实体合并与依存解析

```

 │
 ▼
```

自定义管线组件：


span 匹配规则：

| 来源 | 规则 |
|---|---|
| 实体词表 | 名称 + 别名，中文子串，英文按词边界 |
| 对象词表 | 名称 + 别名，同上 |
| 拉丁人名 | 大写开头多词，如 Harvey C. Jones |
| 排序 | 起点升序，长度降序 |
| 去重叠 | 长词优先 |

谓词抽取规则：

| 步骤 | 规则 |
|---|---|
| 1 | 取 ROOT 动词 |
| 2 | 若 root 是引述动词，下钻 ccomp/xcomp/parataxis 动词 |
| 2b | root 不是动词（根是名词/形容词）时，补 acl/advcl/relcl/conj 动词 |
| 2c | root 是动词时，也补 acl/advcl/relcl 定语/状语从句动词 |
| 3 | 主语 = nsubj/nsubjpass/nsubj:xsubj 子节点 |
| 4 | 主语再加其 conj 子节点（并列主语） |
| 5 | 宾语 = dobj/obj/attr 子节点 |
| 6 | 宾语再加动词的 conj 名词子节点（枚举头） |
| 7 | 补语 = attr 及 cop 结构 |
| 8 | 介词宾语 = nmod:prep，按 与/和/为/至/对/由/在 分类 |
| 9 | 动词没有句法宾语时，取动词后最近的名词短语兜底（"创维推出显示器"根是名词，靠这条拿到宾语） |

无 root 返回空；解析抛异常跳过该句并计数。

### 6.3c 三元组提取选型结论（2026-11-18，修正版）

| 项 | 说明 |

### 6.5 fill.py：关系判定、优先级与槽位填充

关系判定流程：

```
谓词动词
 │
 ├─ 动词本身在动作词表 ──────────► 命中
 ├─ 动词是 compound:vc 里的动词 ─► 命中
 ├─ 子句名词在动作词表 ─────────► 名词触发，B 上限
 └─ 都不在 ─────────────────────► 丢弃
 │
 ▼
动作 id → 21 类之一
 │
 ▼
同一子句多关系 → 按优先级表保留（见 7.8）
```

主语解析：

```
主语 token
 │
 ├─ 落在词表 span 里 ──► 取实体 id / 名称 / 类型
 ├─ 未登录 ───────────► 开放实体规则（7.4）；主语位置上的 2~5 字中文专名/英文大写词按开放实体收
 ├─ 无主语 token ─────► 继承上一个解析出的主语；再退文章主体（标题或导语里最像主体的实体）
 └─ 代词/纯数字/修饰 ─► 丢弃
 │
 ▼
多主语（并列）
 │
 ├─ 对称关系（合作/收购/评测）→ 主体取文章主体，其余进合作方
 └─ 非对称关系（发布/融资/人事/裁员）→ 优先文章主体，否则最靠前

主语继承原生三元组评测（不经过我们的 fill 规则，只看各工具自己的解析结果；62 条带人工 parse_roles 的中文样本）：

| 方案 | 短语能对上 | 完整主谓宾 | 主对宾错 | 主错宾对 |
|---|---|---|---|---|
| spaCy 默认 | 43 | 11 | 24 | 20 |
| spaCy + 自定义分词 | 43 | 11 | 24 | 20 |
| LTP 4.2 | 45 | 23 | 28 | 35 |
| HanLP 2.1 | 44 | 15 | 29 | 25 |
| SuPar 1.1 | 39 | 13 | 24 | 21 |

分词拆分差异（同一批句子，实测）：

| 句子 | spaCy | LTP | HanLP |
|---|---|---|---|
| 百度推出词元所 | 词元 / 所 | 词元所 | 词元所 |
| qData 数据中台开源版 v1.6.7 发布 | qDat / a / v / 1.6 / . / 7 | 数据 / 中 / 台 | 数据 / 中台 |
| 英伟达任命 Harvey C. Jones 为董事 | 英伟 / 达 | 英伟达 | 英伟达 |

结论要点：解析器不是唯一瓶颈——spaCy 原生能给出 11 条完整三元组，但端到端只命中 2 条，
说明**规则/槽位层丢得更多**；LTP 原生最强（23 条），换解析器要配套改规则才有意义。

说明：继承链只看"解析出的主语"，不要求上一子句已经出卡；文章主体先取标题，
标题找不到实体再取导语第一句。继承来的主语一律只出 B 档，理由码 `subject_inherited`。
```

## 8 判档与质量

### 8.1 判定树

见 6.6 的图。

### 8.1b B 档扩展通道

为了在不污染 A 档的前提下补召回，以下三类只出 B 档：

| 通道 | 触发 | 理由码 |
|---|---|---|
| 主语继承 | 无主语 token，继承上一解析主语/文章主体 | subject_inherited |
| 名词性事实 | 名词触发词出卡（见 7.8） | noun_trigger |
| 多宾语拆分 | 同一谓词多个不同宾语，各出一条 | 无（主语是受控实体时可 A） |

A 档条件不变：受控实体主语 + 依存确认主宾 + 对象类型匹配 + 无否定/传闻/标题兜底。

### 8.1c A 档守卫（命中就降 B，不丢卡）

判档返回 A 之前再过一遍守卫；命中任意一条就降 B（卡片仍保留，召回统计不受影响）：

| 守卫 | 触发条件 | 理由码 |
|---|---|---|
| 对象质量 | 对象为空、少于 2 字、超过 30 字 | a_guard_object_missing / too_short / too_long |
| 标题片段 | 对象含 丨、竖线、叹号、问号、分号 | a_guard_title_fragment |
| 泛词对象 | 对象只是模型/平台/系统/产品/服务/供应商等泛词 | a_guard_generic_object |
| 中英碎片 | 对象同时含英文和空格（拼接残留） | a_guard_mixed_fragment |
| 金额校验 | 融资/价格类，对象既没有数字也没有实体 id | a_guard_amount_missing |
| 合作方校验 | 合作方不是公司/人物/机构，或合作方=主体 | a_guard_partner_not_entity / partner_self |
| 人事校验 | 缺人物、缺职务、职务是身份词（联合创始人）、职务不在证据句 | a_guard_person_missing / role_missing / role_identity / role_absent |
| 评测对象 | 对象不是实体/产品 | a_guard_benchmark_no_target |
| 主语校验 | 主语不在证据句，或主语是继承来的 | a_guard_subject_absent / a_guard_inherited |

### 8.2 常见误判与处理

| 场景 | 例子 | 处理 |
|---|---|---|
| 修饰语当主语 | 智能化提供技术储备 | 主语非实体 → C |
| 介词宾语当主语 | 为电动化、智能化提供… | 类型不符 → C |
| 枚举截断 | Search、Fetch…等接口 | 取枚举头名词，否则 B |
| 引述转述 | 消息称…洽谈 | rumor → B |
| 否定 | 并没有提供 | 负极性 → B |
| 引用发言 | 黄仁勋表示… | 事件在 ccomp，取 ccomp 主语 |
| 历史回顾 | 今年3月，比亚迪推出… | 记 event_time |
| 被动句 | X 被 Y 收购 | 主体 Y，对象 X |
| 省略主语 | 推出后又降价 | 继承前文主语，降 B |
| 英文否定 | did not announce | 负极性，降 B |

### 8.3 复核与告警

| 项 | 规则 |
|---|---|
| 频率 | 每周一次 |
| 抽样 | A 档随机 20 条 |

只存事实卡，不存全文；全文只在 artifact，30 天过期。

B 档全量落盘后体积明显超过原估算（原因是主语继承、名词性事实、多宾语三条 B 通道）。
轮转工具已实现：`scripts/kg_facts.py prune --keep-b-days 90`（默认 dry-run，加 `--apply` 才真删），
规则为 **A 永久保留、B 只留最近 90 天**；是否启用由用户定，未启用时默认全量保留。

回填范围原生三元组评测（不经过我们的 fill 规则，只看各工具自己的解析结果；62 条带人工 parse_roles 的中文样本）：

| 方案 | 短语能对上 | 完整主谓宾 | 主对宾错 | 主错宾对 |
|---|---|---|---|---|
| spaCy 默认 | 43 | 11 | 24 | 20 |
| spaCy + 自定义分词 | 43 | 11 | 24 | 20 |
| LTP 4.2 | 45 | 23 | 28 | 35 |
| HanLP 2.1 | 44 | 15 | 29 | 25 |
| SuPar 1.1 | 39 | 13 | 24 | 21 |

分词拆分差异（同一批句子，实测）：

| 句子 | spaCy | LTP | HanLP |
|---|---|---|---|
| 百度推出词元所 | 词元 / 所 | 词元所 | 词元所 |
| qData 数据中台开源版 v1.6.7 发布 | qDat / a / v / 1.6 / . / 7 | 数据 / 中 / 台 | 数据 / 中台 |
| 英伟达任命 Harvey C. Jones 为董事 | 英伟 / 达 | 英伟达 | 英伟达 |

结论要点：解析器不是唯一瓶颈——spaCy 原生能给出 11 条完整三元组，但端到端只命中 2 条，
说明**规则/槽位层丢得更多**；LTP 原生最强（23 条），换解析器要配套改规则才有意义。

说明：v3 的 `v3-output-*` artifact 从 2026-11-09 才开始有，GitHub 上只保留到这一天，
所以本地最多回填 8 天（11-09 ~ 11-16）；30 天回填需等 artifact 积累或从别的历史库补。

C 样本池：每天留 100 条被丢弃的候选，写 `data/kg_debug/c-{date}.jsonl`，只进 artifact 不进 git，供每周看「为什么被丢」。
