# 推荐引擎调研 + 标注↔推荐一致性审查（v5 补充）

> 回答两个问题：
> 1. 业内新闻推荐在类似场景下有哪些成熟方案？
> 2. Stage 2 的标注在 Stage 3 推荐里到底怎么用？标注规则是否合理？
> 本文件补充/修订 v4 的 §1（标注）与 §4（精排）。

## 1. 业内成熟方案

### 1.1 通用架构：多阶段漏斗

新闻推荐工业界的共识架构是「召回 → 粗排 → 精排 → 重排」：

| 阶段 | 目标 | 常用方法 |
|---|---|---|
| 召回 Recall | 从海量内容中取千级候选 | 多路召回：热门、时效、内容相似、主题、地域、协同过滤 |
| 粗排 Pre-rank | 千级 → 百级 | 轻量模型/规则（LR、双塔、规则） |
| 精排 Rank | 百级 → 十级 | 深度模型（DIN/DIEN/MMoE）、LTR（LambdaMART）、LLM 评审 |
| 重排 Re-rank | 十级 → 展示位 | 多样性（MMR/DPP）、去重、时效、业务规则 |

参考：Google News、今日头条、腾讯新闻等公开架构分享都是这个范式；MIND 数据集（Microsoft News Dataset, `msnews.github.io`）是该方向的公开基准。

### 1.2 内容冷启动（我们的情况）

我们**没有用户行为数据**，NRMS/NAML 这类“用户-新闻交互”模型用不上；对应业内做法是：

- **内容特征 + 编辑先验**（Apple News 的人工编辑 + 算法混合）；
- **热门/时效衰减**（Hacker News gravity 公式、Reddit Wilson score）；
- **LLM 评审排序**：LLM-as-a-Judge（Zheng et al., arXiv:2306.05685）、RankGPT（Sun et al., arXiv:2304.09542）——用 rubric 打分或成对比较，适合无标注冷启动。

### 1.3 多样性重排

- **MMR**（Maximal Marginal Relevance，Carbonell & Goldstein, 1998）：相关性 - λ × 与已选集合的相似度；
- **DPP**（Determinantal Point Processes）：YouTube 曾用于“多样化推荐”（Wilhelm et al., 2018）；
- 新闻场景常用“主题/主体覆盖约束 + MMR”。

### 1.4 反馈闭环与探索

- **Bandit**（LinUCB/Thompson Sampling）：在少量展示位上探索新主题/新来源；
- **编辑反馈**：人工“采纳/否决/修改”作为偏好标签，积累后升级 LTR（Learning to Rank）。

### 1.5 评估体系

- 离线：NDCG@k、MRR、precision@k（人工/LLM 标注）；
- 一致性：LLM pairwise 与人工 pairwise 的一致率；
- 在线：shadow 运行、A/B、编辑采纳率；
- 冷启动期以“人工 rubric 抽样”为主。

## 2. 我们的选型（对齐业内）

结合“单出品方、无用户、日更、候选少（几十条）、编辑质量优先”的约束：

```
召回：规则多路（时效/主题/主体/证据/连续性）→ 候选 30–50
粗排：规则 + 轻量分（可解释）→ 候选 15–20
精排：LLM 按 rubric 打分（或 pairwise）→ 分数
重排：MMR/主题覆盖 + 去重 + 时效衰减 → top 8
反馈：编辑采纳/否决 → 积累偏好 → 后续升级 LTR；bandit 探索少量位置
```

这与业内“多阶段 + 冷启动 LLM 评审 + 多样性重排”一致，且保留可解释性。

## 3. 标注↔推荐一致性审查

### 3.1 标签 → 消费者（正向）

| Stage 2 标签 | Stage 3 粗排 | Stage 3 精排 | Stage 4 点评 | Stage 5 文稿 |
|---|---|---|---|---|
| subjects（主体+权重） | 相关性/主体过滤 | impact、多样性 | 背景/主体 | 章节分组 |
| object_type | 相关性 | novelty、narratability | 事实分类 | 解释深度 |
| action | 排除广告/招聘 | narratability | 动作描述 | 章节主题 |
| tech_stack | 技术栈过滤 | audience_fit | 影响范围 | 解释深度 |
| regions | 地域过滤 | （当前未用） | impact | 少用 |
| lifecycle | 时效分层 | （当前未用） | 背景（新/持续） | “后续进展” |
| evidence_tier | 证据门槛 | risk/evidence（重复） | facts 可信度 | 少用 |
| topics | 主题过滤 | 多样性/受众 | 分组 | 章节分组 |

### 3.2 特征 → 标签（反向检查）

| Stage 3 特征 | 需要什么标签/数据 | 现状 |
|---|---|---|
| impact | subjects.weight、object 重要性 | ✅ 有，但权重静态 |
| novelty | 新版本/新数字/新主体 | ❌ 缺“novelty_numbers”标签 |
| momentum | source_count、sequence、6h 增量 | 🟡 有统计，无 growth 标签 |
| audience_fit | tech_stack + 受众画像 | ❌ 缺 audience_persona |
| narratability | 动作+数字+冲突/对比/首次 | ❌ 缺 narrative_angle |
| evidence | evidence_tier 及各分量 | 🟡 重复计数风险 |
| risk | rumor/single source/sensitivity | 🟡 缺 sensitivity 标签 |

### 3.3 发现的问题

**A. 循环/重复使用（会导致排序偏差）**

1. `lifecycle` 由 `source_count/sequence/时间` 推导，而精排的 momentum 又用这些原始量 → **同一信息用两次**；
2. `evidence_tier` 既是粗排门槛，又进精排 risk/evidence → **双重计数**；
3. `subjects.weight` 同时决定“相关性过滤”和“impact” → 高权重主体容易双倍加分。

**B. 白标（标了没用）**

- `regions`、`object_type` 在精排几乎没用；
- 标签的 `confidence` 完全没被消费；
- `topics` 只在粗排用，精排未参与多样性。

**C. 漏标（推荐需要但没有）**

1. `novelty_numbers`：新版本号/新金额/新分数/新日期（novelty 的直接证据）；
2. `narrative_angle`：冲突/对比/首次/纪录/反转（可讲性）；
3. `audience_persona`：开发者/投资人/消费者/政策制定者；
4. `sensitivity`：事故/监管/诉讼/伦理（风险与措辞）；
5. `quote_availability`：是否有官方声明/可引用原话；
6. `momentum_growth`：6h 内来源数增量（势头）。

**D. 规则不合理**

1. **动作单标签 + 硬优先级**：一条新闻可能同时“发布+开源+融资”，单标签会丢信息；
2. **主体权重静态**：靠人工拍权重，无法反映真实影响力；
3. **生命周期阈值拍脑袋**：24h/3 来源没有数据依据；
4. **证据公式权重拍脑袋**：且与排序重复；
5. **实体别名歧义**：“苹果/小米/Meta”等既可能是公司也可能是普通词，需要上下文校验；
6. **对象/技术栈多标签**：只取单值会丢信息。

## 4. 修订后的 Stage 2 标注规范 v2

### 4.1 原则

1. **标注只产出“事实/属性”，不产出“分数/排名”**；分数一律在 Stage 3 计算，避免循环；
2. 每个标签必须有**消费者**（Stage 3/4/5），没有消费者的标签不标；
3. 每个标签带 `value`、`confidence`、`method`（rule/llm）；
4. 多标签优先，单值只在语义上唯一时使用；
5. 标签定义放 `config/nlp/*.yaml`，可迭代。

### 4.2 标签清单（保留 + 新增 + 废弃）

| 标签 | 类型 | 方法 | 消费者 | 变更 |
|---|---|---|---|---|
| subjects | 实体列表（id/weight） | 词典+别名+上下文校验 | 粗排/精排/点评 | 保留（加 confidence） |
| object_type | 多标签 | 对象词典+句式 | 精排/点评 | 保留 |
| action | 多标签+primary | 动词表 | 粗排/精排/点评 | 改为多标签 |
| tech_stack | 多标签 | 关键词表 | 粗排/精排 | 保留 |
| regions | 多标签 | 词典+HQ 映射 | 粗排/点评 | 保留（精排暂不用） |
| lifecycle | 单值 | 推导（规则） | **仅粗排/点评** | 禁止进精排（去循环） |
| evidence_tier | 单值 | 公式 | **仅粗排门槛** | 禁止进精排（去重复） |
| topics | 多标签+primary | 词典 | 粗排/精排多样性 | 保留 |
| **novelty_numbers** | 列表 | 正则（版本/金额/分数/日期） | 精排 novelty | 新增 |
| **narrative_angle** | 多标签 | 词典（冲突/对比/首次/纪录/反转） | 精排 narratability | 新增 |
| **audience_persona** | 多标签 | 规则（技术栈/对象映射） | 精排 audience_fit | 新增 |
| **sensitivity** | 单值 | 词典（事故/监管/诉讼/伦理） | 精排 risk/点评措辞 | 新增 |
| **quote_availability** | 布尔 | 检测引号/官方声明 | 点评/文稿 | 新增 |
| **momentum_growth** | 数值 | 来源数 6h 增量（需历史） | 精排 momentum | 新增 |
| confidence | 数值 | 每条标签自带 | 全链路 | 新增（消费） |

### 4.3 修订后的规则

1. **动作**：输出 `primary_action` + `actions[]`；优先级只用于选 primary，不丢其他；
2. **主体**：词典 + 上下文窗口（同句/邻近词含科技词）才计；别名冲突降 confidence；
3. **权重**：初始分档（头部/中部/长尾），可被编辑配置覆盖；后续用“被选中频率”校准；
4. **生命周期**：阈值配置化，先跑数据再定；只用于粗排/点评；
5. **证据**：公式参数配置化；`evidence_tier` 只作门槛，精排用其“分量”（未重复的独立信号）；
6. **地域**：明确“全球/未知”值，避免误配。

## 5. 修订后的 Stage 3（对齐业内）

```
召回（30–50）
  ├─ 时效召回（新/持续/长尾）
  ├─ 主题/技术栈召回
  ├─ 主体召回（重要公司/实验室）
  ├─ 证据召回（官方/多源）
  └─ 连续性召回（旧事件新进展）
粗排（15–20）
  └─ 规则：相关性、证据门槛、去重/覆盖、风险排除、多样性预筛
精排
  ├─ 规则分（可解释特征：impact/novelty/momentum/audience/narratability/risk）
  └─ LLM rubric 分（top 20，成对比较或打分）
重排
  ├─ MMR/主题覆盖（同主体/同技术栈 ≤2）
  ├─ 去重（对 ledger/已选）
  └─ 时效衰减
输出 top 8 + 理由 + 证据包
```

- **冷启动**：规则 0.6 + LLM 0.4（与 v4 方案 D 一致）；
- **反馈升级**：积累编辑采纳/否决后，切 LTR；bandit 探索少量位置；
- **评估**：离线回测 + rubric + NDCG/precision + pairwise 一致率 + shadow。

## 7. 推荐逻辑（白话版）

一句话：**先按规则圈出“候选”，再用六个维度打分，最后按多样性/时效做重排，选出 8 条给编辑和播客。**

### 7.1 第 0 步：输入

当天“资讯潮”里约 30–50 个**事件**（同一事件的多源报道已合并）。

### 7.2 第 1 步：召回（30–50 → 约 20）

只做“资格判断”，不打分：

| 召回通道 | 规则 |
|---|---|
| 时效召回 | 新事件 ≤48h；持续事件 ≤7 天；长尾 ≤30 天 |
| 主题召回 | 命中 AI 主题/技术栈（LLM、Agent、芯片、机器人…） |
| 主体召回 | 命中重要公司/实验室（OpenAI、DeepSeek、NVIDIA…） |
| 证据召回 | 官方来源，或独立来源 ≥2 |
| 连续性召回 | 历史事件有新进展（新版本/新数字/新动作） |

### 7.3 第 2 步：粗排（约 20 → 15）

| 规则 | 动作 |
|---|---|
| 已播报过（覆盖账本命中） | 淘汰 |
| 单一来源 + 传闻 | 淘汰或降权 |
| 招聘/课程/广告/榜单 | 淘汰 |
| 同一主体超过 2 条 | 先留 2 条 |
| 事实/数字跨源矛盾 | 标记待核，暂不推荐 |

每条记录“为什么留下”，进入精排。

### 7.4 第 3 步：精排（15 → 10）

每条新闻按 6 个维度打 0–5 分：

| 维度 | 看什么 |
|---|---|
| 影响力 | 主体有多重要、影响范围多大（全球/中国/行业） |
| 新颖度 | 是否新发布/新版本/新数字/新主体 |
| 势头 | 来源数增长快不快、是否持续事件的新进展 |
| 受众相关 | 开发者/从业者/投资人是否关心 |
| 可讲性 | 有没有数字、对比、冲突、反转，能不能讲成故事 |
| 证据与风险 | 来源质量、是否官方、是否有传闻风险 |

打分方式：

- **规则分**：可量化特征直接算（来源数、新版本号、主体权重…）；
- **LLM 复核**：只对前 20 条，用固定 rubric（每档有明确描述）输出 JSON 分数 + 一句理由；
- 最终分 = **0.6 × 规则分 + 0.4 × LLM 分**（冷启动；后续按编辑反馈调权重）。

### 7.5 第 4 步：重排（10 → 8）

- **MMR 多样性**：同一主体、同一技术栈最多 2 条；
- **主题覆盖**：尽量覆盖不同主题（发布/融资/政策/论文/事故）；
- **去重**：与已播报内容比对；
- **时效衰减**：越旧权重越低。

输出 **top 8**，每条带：分数、推荐理由、证据包（来源 + 原文）。

### 7.6 示例

| 事件 | 影响力 | 新颖 | 势头 | 受众 | 可讲 | 证据风险 | 综合 |
|---|---|---|---|---|---|---|---|
| A：DeepSeek 开源新 Agent 框架 | 5 | 4 | 5 | 5 | 5 | 4 | **4.7** |
| B：NVIDIA 财报超预期 | 5 | 3 | 4 | 4 | 4 | 5 | **4.2** |
| C：某高校新论文 | 3 | 5 | 2 | 4 | 3 | 3 | **3.4** |
| D：某公司 AI 部门裁员（单一来源） | 4 | 3 | 4 | 4 | 4 | 2 | 3.2 |
| E：旧闻重提（已播过） | — | — | — | — | — | — | 淘汰 |

重排时 C 与 D 争第 3 位：C 主题不同（论文）、D 单一来源 → **C 优先**；D 标记待核。

### 7.7 下游怎么接

- **02 深度日报**：编辑对 top 8 中前 5 条写点评（事实/背景/影响/风险）；
- **01 今日主推播客**：从 top 8 里选 3–4 条，结合点评写成 15 分钟双主持稿。

### 7.8 为什么不是“一个模型直接排序”

1. 规则负责**便宜、可解释、可审计**的圈选（召回/粗排/重排）；
2. LLM 只负责**需要判断力**的精排（只处理前 20 条，成本可控）；
3. 多样性/去重/时效由**确定性规则**兜底，避免 LLM 输出不可控；
4. 每一步都记录“为什么选/为什么淘汰”，可回溯、可调参。
