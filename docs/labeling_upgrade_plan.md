# 标签与推荐升级实施方案

## 一、复盘：哪些对，哪些要修正

### 已经对的方向

1. **先定骨架再填词**：枚举/字段/registry 先定，词表后补；
2. **决策标签受控**：模型只能选枚举，不自由生成；
3. **抽取标签开放**：实体/数字从正文抽，再映射规范 id；
4. **规则 + LLM 混合**：规则快筛兜底，LLM 处理语义边界；
5. **覆盖率要度量**：空白率/命中率/饱和曲线，不假设词典完整；
6. **评测先行**：没有金标准，调参就是拍脑袋。

### 我之前说错/说不严谨的

| 之前说法 | 修正 |
|---|---|
| “形容词改成刻度，就不用穷举同义词” | 错。刻度是输出表示，输入侧仍要穷尽线索词；还要处理否定、程度、语境 |
| “标题带 AI 词就放行” | 是临时门槛，不是最终标准；最终看 ai_centrality + primary_domain + 证据 |
| “来源按 category 分级就够了” | 不够。category 不等于可信度，需要 source registry（官方/媒体/自媒体/研究） |
| “600 条标注够用” | 600 条只够调阈值；上线回归建议 1000 条，且要分层、含“顺带提 AI”的难例 |
| “覆盖率高就说明标签好” | 不充分。还要 precision/recall、混淆矩阵、人工一致性，避免“覆盖了但判错” |

### 之前遗漏的环节

- 标签**证据/置信度/方法**（rule/llm/hybrid）没有统一存储；
- 标签**版本化**与历史 artifact 迁移；
- **实体别名冲突**（同一名字指不同公司/产品）；
- **多语言**标题（中英混合、英文论文）；
- **事件合并后标签被单条 item 带偏**；
- **负样本长尾**（非 AI 类目不可能一次穷举）；
- **人工标注流程**（双人标注、仲裁、一致性）；
- **上线方式**（影子模式、灰度、回滚）；
- **成本/延迟/缓存**（LLM 标注不能每天全量重跑）；
- 编辑/播客质量评测没有纳入。

## 二、目标架构

```
采集（S1）
   ↓
Stage 2 标注
   ├── 规则层：标题/导语 + 词典 + 实体/行业 registry
   ├── LLM 层：只对候选，输出枚举 + 证据句 + 置信度
   └── 合成层：证据/置信度/方法写入 Labels
   ↓
标签仓库（版本化 schema）
   ↓
推荐（S3）：中心性/领域门槛 → 粗排 → 精排 → 重排
   ↓
评测：金标准 + 覆盖率 + 线上抽样
```

## 三、标签分层（最终形态）

| 层 | 内容 | 来源 | 用途 |
|---|---|---|---|
| 证据层 | item_id、原文片段、来源、时间 | 采集/正文 | 审计、事实核对 |
| 抽取层 | 实体、产品、数字、benchmark、引语 | 规则 + NER/LLM | 特征、展示 |
| 决策层 | ai_centrality、primary_domain、object_type、action、audience、narrative、risk | 枚举 + 规则/LLM | 召回/粗排/精排 |
| 派生层 | lifecycle、timeliness、credibility、impact_scope、novelty_score | 公式 | 排序/展示 |

每个标签必须带：

- `value`（枚举或规范 id）
- `evidence`（原文片段，必须能在输入里找到）
- `method`（rule / llm / hybrid）
- `confidence`（0–1）
- `taxonomy_version`

## 四、分阶段实施

| 阶段 | 内容 | 交付物 | 验收标准 |
|---|---|---|---|
| P0 评测基线 | 300 条分层金标准 + 难例（顺带提 AI、汽车、金融、消费） | `data/eval/gold/` + 标注工具 + 指标脚本 | 规则版各阶段指标可复现 |
| P1 标签治理 | dimensions/labels/entities/industries + 版本/校验/别名冲突 | `config/taxonomy/*` + `taxonomy.py` | 非法枚举/重复 id 直接报错 |
| P2 规则升级 | 标题/导语作用域、词表扩展、否定/程度、派生公式 | ocean 标注模块 | 空白率下降；回归不误杀 |
| P3 LLM 标注 | 批量枚举+证据+置信度、校验、缓存、影子模式 | pipeline 语义标注服务 | 与规则对比 precision/recall 提升 |
| P4 推荐标准 | 中心性/领域门槛、source registry、证据独立性、特征重算 | recommend 模块 | top8 精确率/覆盖率达标 |
| P5 采集/去重 | 源健康度、全文解析降级、语义去重、账本口径 | collect/ocean | 源失败可见；重复事件下降 |
| P6 编辑/页面 | 日报/播客点评评测、show notes、页面数据 | editorial/site | 人工抽检通过 |
| P7 运维 | 成本/延迟/告警/回滚/监控 | pipeline/scripts | 单日成本与耗时在预算内 |

## 五、评测设计（防止自欺）

- 金标准来源：人工标注 1000 条（300 调参 + 700 留出），跨 7–14 天；
- 分层：核心 AI、AI 基建、顺带提 AI、汽车、金融、消费、社会；
- 双人标注 + 仲裁，Cohen's kappa ≥ 0.7；
- 指标：每阶段 precision/recall/F1、top8 精确率、误杀率、漏放率、校准曲线；
- 留出集绝不参与调参；规则/LLM 对比同一金标准；
- 每周从线上抽 20 条人工复核，形成回归样本。

## 六、上线与回滚

```
影子模式（只计算、不拦截）
   ↓ 对比指标
小流量门槛（高置信度才用新标签）
   ↓ 观察误杀/漏放
全量启用
   ↓ 异常
配置回滚（开关关闭，回到规则版）
```

所有新门槛默认关闭，按配置开关灰度。

## 七、风险与对策

| 风险 | 对策 |
|---|---|
| 标签体系膨胀 | 每个字段必须有消费者，否则不建 |
| 长尾非 AI 类目穷举不完 | 规则覆盖常见 + LLM 语义兜底 + 人工抽检 |
| LLM 成本/延迟 | 只对候选、批量、缓存、预算上限 |
| 实体别名冲突 | 唯一 id + 别名冲突校验 + 人工仲裁 |
| 标注质量不稳 | 双人标注 + 仲裁 + kappa |
| 历史 artifact 缺新字段 | 版本化 + 默认 unknown + 回填脚本 |
| 改规则引入回归 | 金标准回归 + CI 检查 |

## 八、立即执行的三件事

1. **P0**：把 600 队列扩到 1000，补“顺带提 AI / 非 AI 类目”难例，先标 300 条；
2. **P1**：把 `Labels` 升级为带证据/置信度/方法的版本化结构，历史数据默认 unknown；
3. **P2**：规则层先接 taxonomy（实体/行业用 id），并用 `label_coverage` + 金标准做回归。

P3 的 LLM 标注必须在 P0/P1/P2 之后，否则没有基线、没有证据字段、没有回归标准。
