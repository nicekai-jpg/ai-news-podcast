# 从采集到推荐：第三套方案的分层设计与执行状态

> **为什么有这份文档**：这套方案（下面简称 L1–L4）当初是在对话里提出的，
> 没有落成文档，导致后续几轮各自推进、难以核对进度。这里把它固定下来：
> 设计是什么、哪一层做到了哪一步、哪些还没做。
>
> **一句话结论：这套方案没有完成。**
>
> 原始目标是「把数据采集好、把推荐做好」。其中**只有 L1 采集达成**；
> L2 零进展（只做诊断、未改任何代码）；L3 的原始设计被实测否定、改为核查资产；
> L4 推荐：**指标口径已修正**（2026-11-26）。原先按「8 条 shortlist 里几条值得播」衡量，
> 实测发现真正的瓶颈是**槽位不够**——每天粗排前 20 名里有 54%~75% 值得播，只取 8 条会浪费一半。
> `shortlist_size` 已由 8 放宽到 15，同一批测试日捞回的正例从 28 条升到 42 条。
> 详见 `docs/todo.md` 的 N1。

## 0 三套方案的关系

项目历史上并行过三条路线，第三套是「把前两套的优点结合」：

| 方案 | 内容 | 结局 |
|---|---|---|
| ① 线上旧管线 | RSS 抓取 → LLM 写稿 | 被 v3 取代，保留回滚 |
| ② KG 零 LLM 事实层 | 依存句法抽三元组 → 事实卡 | 产物保留，**不进推荐** |
| ③ **第三套（本文件）** | 采集 → 归一/聚类 → 事实抽取 → 推荐，分层治理 | L1 达成；L2 有测量手段；L3 定位改变；L4 槽位已放宽 |

## 1 分层设计与执行状态

```
L1 采集 ──→ L2 归一/聚类/标注 ──→ L3 事实抽取 ──→ L4 推荐
 达成         有金标了             原目标放弃        槽位 8→15
 129 源       P/R 可测             改做核查         每天捞回 28→42
```

**整体完成度：4 层里只有 1 层达成。** 下面的「✅ / ⚠️」只描述**工作进展**，
不代表**目标达成**；「已到上限」= 现有规则特征已到极限，不是「做好了」。

| 项 | 结果 |
|---|---|
| 源数量 | 130 个（启用 111，禁用 19） |
| C3 路由失败 | 8 → **2**（`pixelstech_ai` / `juejin_aicoding` 仍有波动） |

**根因记录**：C3 全部指向同一 RSSHub 容器，与外部站点共用 24 并发会被压出 503。

**剩余**：`pixelstech_ai`、`juejin_aicoding` 上游本身不稳定，待观察是否禁用。

### L2 归一/聚类/标注：⚠️ 只做了诊断，未改动

**做的**：
- 验证四层去重是正确的（571 → 494），跨媒体重复极少（903/1027 是同媒体转载）；
- 验证聚类接近空操作（470 事件里 455 个是单条目），**这是语料事实，不是缺陷**；
- 量化了标注空白率。

**当前标注空白率**（2026-11-25，539 事件）：

| 字段 | 空白 | 影响 |
|---|---|---|
| `subjects` | 32% | S3 的 subject 召回通道、impact 特征 |
| `narrative_angle` | 34% | `howto` 降权信号依赖它 |
| `tech_stack` | 29% | audience_fit 特征 |
| `object_type` | 24% | narratability 特征 |
| `topics` | 17% | topic 召回通道 |
| `actions` | 12% | 粗排动作加分 |

**未做**：
- 没有标注金标 → **无法测标注的 precision/recall**，只能看空白率；
- 空白率的改进没有闭环验证手段。

**这是 L2 最大的缺口**：S3 的所有特征都来自这里，但没有办法证明改词表是变好还是变坏。

### L3 事实抽取：⚠️ 设计前提被否定，定位已改变

**原设计**：零 LLM 抽事实卡（A/A2/B/C 档）→ 作为 S3 推荐的强特征。

**实测结论（`docs/kg_triple_benchmark_method.md`）**：

| 指标 | 值 |
|---|---|
| 非 LLM 三元组 F1（60 篇统一金标） | **0.01 – 0.03** |
| A 档覆盖率（事件级） | **0.74% – 1.6%** |
| A 档精度（抽样 12 条） | ~83% |
| 日报 top5 里能对上 A 档 | 13.3% |

**结论**：覆盖率远低于文档写死的 30% 启用阈值，`inject_verified_facts` 保持 `false`。
L3 定位改为**产物归档 + 人工核查工具**（`kg_facts audit/watch/coverage`），不作为推荐特征。

**未做**：HanLP 2.1 MTL 迁移（`docs/kg_extraction.md` §6.3c）**建议不做**——
端到端仍会是 0.03 量级，投入产出不成比例。

### L4 推荐：⚠️ 指标口径已修正，槽位已放宽（2026-11-26）

**原口径下的结论**：P@8 = 0.59（8 天）/ 0.62（17 天），即每 8 条 shortlist 有 3 条不值得播。

**新发现：这个指标问错了问题。**

补齐 11-12~11-25 每天粗排前 20 名的标注（新增 208 条，正例 61%）后发现，
**每天的池内正例占比高达 54%~75%**：

```
一天有 22~24 条候选 → 其中 13~18 条值得播 → 但只播 8 条
```

问题不在「排不准」，在「槽位不够」。改 `shortlist_size` 8 → 15 后，同一批测试日：

| | 改前 | 改后 |
|---|---|---|
| 5 天捞回正例 | 28 | **42** |
| 精确率 | 0.70 | 0.67 |

**已证否的调参路（累计六条）**（详见 `docs/recommend_evaluation.md`、`docs/todo.md` N1）：

| 实验 | 结果 |
|---|---|
| LLM 精排（占 40% 权重） | 0.59 → 0.58 |
| 事件性闸门（LLM 判 is_event） | 0.82 vs 0.82，零差异且误杀 2 条 |
| 粗排公式按特征区分度重排 | 全部变体 ≤ baseline |
| 放宽门槛（cap/rumor gate） | 粗排正例 50→141，但 P@8 0.59→0.44 |
| `subject_cap` 截断顺序 | 426 组里被截正例分数**从未**更高，顺序没错 |
| 拆 `subjects`（只留主位主语） | 41.6% 的 subject 来自正文，但删掉后 P@8 → 0.57 |

有正收益且已保留的三条：
1. `rerank.max_per_tech_stack` 2 → 6（0.56 → 0.85）
2. 活动/教程类降权（0.49 → 0.58）
3. `rerank.shortlist_size` 8 → 15（捞回正例 28 → 42）

## 2 还没做的事（按优先级）

### P0 金标规模

| 项 | 现状 | 需要 |
|---|---|---|
| 推荐金标 | 8 天 / 64 个已判槽位 | **≥20 天**（n≥30 才有统计意义） |
| 标注金标 | **无** | 200 事件，测 subjects/tech/topic 的 P/R |

没有这两项，任何调参结论都是噪声。本轮已多次验证：3 天样本得出 0.85，
8 天后变成 0.59。

### P1 标注质量闭环

L2 的空白率（subjects 32%、narrative 34%）是目前唯一还没建立测量手段的环节。
需要：

1. 抽 200 个事件人工标注 `subjects / tech_stack / topics`；
2. 跑 `precision/recall`，而不是只看空白率；
3. 按漏标清单补词表 → 回归测试。

### P2 候选池的「事件性」

L4 的瓶颈是「看似重要但无具体事件」的内容（观点稿、复盘、早报汇编）占满候选池。
关键词和 LLM 闸门都试过，都不行。

**可能的下一步**：把「事件性」做成 L2 的结构化信号（例如要求 `primary_action`
必须在标题命中、或引入轻量分类器），而不是在 L4 事后过滤。

## 3 已明确「不做」的事

| 项 | 原因 |
|---|---|
| HanLP 2.1 MTL 迁移 | 端到端 F1 仍 0.03 量级，投入产出不成比例 |
| 事实层作为推荐特征 | 覆盖率 1.6%，远低于 30% 阈值 |
| 自动应用 S5 的 corrections | 5 条抽查全部需语义改写或补充外部信息，机械套用会引入错误 |
| 继续在 L4 调权重/词表 | 四条路已证否 |
| 跨天 shortlist 屏蔽 | +0.02 属噪声，且会误杀连续报道 |

## 4 如果继续推进，建议的顺序

1. **等 3 天**看新源与 C3 稳定性（自动任务已设）；
2. **扩金标**：推荐 8 → 20 天，标注从 0 → 200 事件；
3. 用扩充后的金标重测 L1–L4，确认 0.59 是否稳定；
4. 若稳定，再考虑替换规则排序（轻量模型），而不是继续调规则。

**前提**：没有 P0 的金标，第 3、4 步都不该开始。
