[CHAPTER] 安全新入口

[Host A] 说到这个，必须提醒咱们注意 AGENTS.MD。它原本是给智能体看的项目说明，现在却可能变成新型攻击入口，这事儿听着就让人后背发凉。

[Host B] 问题在于，开发者把它当文档，智能体运行时却可能把它当高优先级指令。只要仓库里藏进恶意内容，自动读文件的代理就可能把坏命令当成任务要求。

[Host A] 真的假的？比如一个看起来再正常不过的项目说明，智能体读完后却顺手读取凭据、修改依赖，或者把本不该外传的内容带出去。

[Host B] 所以危险不只在模型会不会上当。只要代理拥有仓库读写、执行命令和访问密钥的权限，恶意指令就可能借它现有的手办坏事，模型拒绝一次也挡不住所有路径。

[Host A] 这就像员工手册里夹着一页伪造的财务指令。以前咱们防外部攻击，现在还得防进入上下文的假老板，而且攻击者已经顺着开源依赖和代码仓库混进来。

[Host B] 防线也得跟着改。AGENTS.MD 应该被视为需要校验来源的上下文，而不是天然可信；工具权限要最小化，敏感凭据要隔离，高风险动作要有人确认。

[Host A] 再加上沙箱、出网限制和完整审计，智能体闯祸以后还能查清楚。安全不能只靠一句系统提示词，更不能把项目说明文件当安全区。

[Host B] 对普通开发者来说，使用代码代理前得先看仓库带了什么指令，能读什么目录，能执行什么命令。Agent 越能干，权限边界越得清清楚楚。

[Host A] 而且接 API 比让人远程操作云桌面顺得多。个人智能体可以先在沙箱里装依赖、跑测试、整理文件，再把结果交回来，执行链路一下就完整了。

[Host B] 但别只看方便。持久环境会留下数据，沙箱也得管理生命周期和费用。凭据怎么注入、结果怎么回收、容器何时销毁，都要在接入前设计清楚。

[Host A] 另一个亮点是 STEPX Neo 智能体手机亮相进博会，高通展台展示软硬模一体化方案。咱们终于不用总隔着电脑屏幕跟智能体说话了。

[Host A] 不过手机也是权限重灾区。录音、通讯录、定位和跨应用操作都敏感，用户得清楚智能体看见了什么、做了什么，最好还能随时收回授权。

[Host A] 新闻聊完了，接下来进入今天的项目雷达时间。主推仓库是 amosblomqvist/learnharness，定位原文是“Agent harness for learning difficult things.”

[Host A] 怎么跑？按 README 原样执行 npm ci、npm run dev、npm test，顺序别改。先把依赖装稳，再启动开发环境，最后跑测试确认基础链路没坏。

[Host B] 其中 npm test 会验证 fixtures 和 fake providers。也就是先用可控假数据把流程测通，不急着烧真实模型额度，这比一上来就接昂贵接口稳妥多了。

[Host A] 想做差异化，可以保留通用 harness，只增加一个垂直学习场景的 fixtures、提示词与验收规则，把它改成特定领域的智能陪练。

[Host B] 然后替换 fake provider，接入真实模型并记录学习进度。这样内容与反馈就能形成差异，不过真接模型前，隐私、费用和失败重试也得测扎实。

[Host A] 还有 AGPL-3.0 这道门槛得先看明白。如果 fork 后拿去做网络服务，开源许可的义务要认真核对，别代码跑通了，许可却踩线。

[Host B] 所以这仓库适合先读源码、跑 fixture，再做小改动验证学习闭环。它的价值不只在热度，而在于提供一个能替换模型、能定义验收标准的实验骨架。
